## T1 acceptance (pending stage 2)

- [x] `Period` persists inclusive calendar `starts_on` and `ends_on` dates with start no later than end; its derived total/elapsed day calculations include both boundaries, clamp before/after the interval, and do not hardcode a quarter length. Instance save validation rejects inclusive endpoint overlap and multiple active periods; a closed period cannot be reopened or edited, and its targets cannot be changed through the tested instance/Admin write paths. Cross-row validation is not a database-wide concurrency guarantee.
- [x] `MetricItem` is a catalog with a unique name under exact database equality; no case/whitespace normalization or synonym reconciliation is claimed.
- [x] `StaffTarget` uses required protected staff/period/item FKs, a database uniqueness constraint on `(staff, period, item)`, decimal `goal > 0`, decimal `weight_percent` in `[0, 100]`, and optional nonnegative decimal `legacy_progress`. It is provisional, not verified evidence. Draft weights may be incomplete; `weights_ready` only reports nonempty, exactly-100% weight eligibility per staff/period, not a score or an atomic cross-row guarantee.
- [x] Admin registers all three models with list/search/filter where relevant and guards closed period/target change and delete; synthetic Admin client tests exercise creation, edits, invalid input, search and read-only details. Admin bulk actions for periods/targets are disabled; queryset update/delete, bulk writes and concurrent writes can bypass instance rules. No global authorization is claimed.
- [x] Initial migration was generated and inspected with `cuentas.0001_initial` dependency and only three new tables. `makemigrations --check --dry-run` found no drift; nine focused tests passed for supported date, overlap, active, closure, target range/uniqueness, weight and Admin paths.
